# 项目驱动的教学详实度与零基础叙述规范

`from-zero` 的核心挑战在于同时守住两条底线：**既要让零基础读者凭这一个网页彻底看懂所有概念、原理、流程与代码细节，又绝不能把不同项目塞进同一套模板里。**

---

## 一、自底向上知识盘点（Bottom-up Inventory）

在动手写网页前，必须先从**当前给定项目的真实源码或规格**中提取三份内部分析清单（仅用于核查是否讲漏，**绝不直接照搬成固定页面结构**）：

1. **真实术语与语法障碍清单**：
   - 逐行扫过核心文件，找出新手会卡壳的专有名词（如 `REST API`、`WAL 模式`、`devicePixelRatio`、`Shadow DOM`、`Service Worker`、`CSP`）与陌生语言语法（如可选链 `?.`、展开运算符 `[...arr]`、`CASE WHEN`、`e.preventDefault()`、`chrome.runtime.lastError`）。
   - 小项目可能 5~8 个，复杂项目可能 12+ 个，完全依项目真实代码而定。
2. **完整运行与实操流程清单**：
   - 不只写“新增一条数据”的快乐路径，还要盘点**初始化读取、状态修改、删除、异常校验分支、持久化恢复，以及环境启动/浏览器加载与代码修改后的刷新流**，同时列出前后端/模块间的数据结构与接口契约。
3. **核心原理与选型取舍清单**：
   - 找出项目里最反直觉的底层因果链（如 HTTP 文本如何变成 `req.body`、画布放大后为何还要 `ctx.scale`、非对称同步返回为何关闭扩展端口），以及技术选型的“为什么用它 / 代价是什么 / 什么场景下换别的”。

## 二、概念、原理与选型的自然融入（按需分布，零基础过筛）

1. **零基础词汇全过筛（消灭晦涩词）**：
   - 假设读者是**首次接触编程或刚上手 Vibe Coding 的零基础学习者**。凡正文、图表标签或沙盘中出现英文缩写（`HTTP`、`JSON`、`DOM`、`API`、`SQL`、`XSS`、`CSP`、`DPR`）、英文方法/API（`e.preventDefault()`、`JSON.stringify()`、`attachShadow()`）或抽象名词（`中间件`、`沙箱`、`持久化`、`异步回调`、`状态码`、`端口`、`引用类型`），**必须用日常能秒懂的语言讲清“它是什么 + 它在这里干什么用”**。
   - **不要只挑 1~2 个词敷衍**：每个核心章节都应顺手为陌生词挂上 `.term-chip`，并在因果链或 SVG 英文标签旁尽量附带简短中文动作副注（如 `fetch JSON（向后端发数据请求）`）。
2. **主线必懂知识留在主阅读流，严禁偷懒藏进折叠框**：
   - 读者理解当前项目主干必须掌握的概念、核心原理推导与技术选型理由，**必须直接展开在正文、图解或代码旁**。
   - `.deep-dive`（原生 `<details>` 折叠区）仅用于承载锦上添花的底层原理深挖（如 SQLite B-Tree/WAL 底层机制）或语言基础小课堂（如 `?.` 可选链与 `??` 语法），不阻断主线阅读。
3. **形式因词制宜，拒绝固定几段式概念卡**：
   - **轻量术语/陌生语法**：用行内可点开微释义 `.term-chip` 或直接写进代码框下方的 `.annot-item` 注解中，不打断阅读流。
   - **关键机制概念与选型权衡**：用 `.jit-concept` 或自然段落讲清“它在这里扮演什么角色、不用它会出什么真实问题、以及本项目哪一行代码用到了它”——**不要强行给每张卡片套死板统一的固定小标题**。
4. **底层因果推演必须完整**：
   - 讲解机理时，必须把中间环节推导出来：*输入是什么 → 中间经过了什么变换或拦截 → 为什么必须这样算/这样写 → 最终改变什么状态或画面*。
5. **自然平实的中文叙述**：
   - 严禁 `🗣️ 人话翻译：`、`💡 直觉比喻：`、`【大白话日常工作】` 等机械标签；不硬凑牵强比喻；多条模块职责分点分行（`<ul><li>`）展示。

## 三、项目原生可操作微沙盘与操作指引（硬性契约）

- 每个教程必须围绕当前项目最核心的 1~2 个机制，编写**真正运行项目同构逻辑的轻量原生 JS 沙盘**：
  - **顶部必须附带 `.sandbox-guide` 操作指引**：用 1-2-3 步写清「怎么输入/操作 → 怎么切换异常对比 → 去哪里观察结果变化」，绝不让用户对着输入框和一堆按钮发懵；
  - 必须允许学习者**真实输入、绘制、勾选或通过显式按钮触发操作**（不要把重要提交藏在“失焦/双击”等隐晦事件里），并实时计算出新的状态、数据表行、消息信封或画面结果；
  - 尽可能把“为什么不能那样写”的常见坑（如不加 `?` 占位符导致的 SQL 语法崩溃、直接 `.push()` 导致的撤销失灵、漏写 `return true` 导致的端口关闭）做成沙盘里可一键切换对比的真实运行分支。
- **明令禁止**：只做两个按钮切换预设静态文本的伪实验，或只有控件没有操作说明的沙盘。

## 四、真实代码实战与中型仓库（10~40 文件）拆解协议

1. **不得阉割目标项目的真实关键特性**：
   - 不可为了缩短代码框而把项目的核心特性删成玩具（例如全栈项目漏掉修改/删除、画布笔记漏掉 Markdown 联动、扩展漏掉 Shadow DOM 气泡与生词本）。
   - 文件较长时，通过 `data-focus="起始行-结束行"` 提供「仅看核心行 / 展开完整文件」切换，既保持聚焦又不丢完整可跑代码。
2. **高密度精准注解（业务逻辑 + 新手语法双覆盖）**：
   - 每一个实质性代码文件都必须配有足够详尽的 `.annot-item[data-lines="..."]`（与 `tutorial-shell.html` 的双向联动结合，点注解看代码、点代码行看注解），**绝不允许核心文件 0 注解或行号越界**。
   - **HTML 实体二次转义红线**：在 `<pre class="code-pre"><code>` 内展示的 JS 代码字符串若包含 `&amp;`、`&lt;`、`&gt;` 等实体（例如防 XSS 的 `.replace(/&/g, "&amp;")`），源码中必须双写为 `&amp;amp;`、`&amp;lt;`、`&amp;gt;`，否则浏览器解码后会破坏复制到剪贴板的可运行代码。
3. **章节自然生长与中型仓库（10~40 文件）分层策略**：
   - 章节数量与组织顺序完全由项目真实边界与认知负荷决定（`examples/` 中的示例分别采用了 4 节、5 节、6 节等不同节奏，仅作形态参考，严禁当成固定范式）。
   - 面对中型仓库（10~40 文件），先按功能域聚类（3~5 域），提取一条 4~7 个文件的“最小可跑通主干链路”进行高密度精讲；其余辅助文件在可折叠目录树中标明路径与职责，100% 忠于真实源码，不虚构任何模块或函数。
