# 项目分析启发式视角提醒（Inspection Prompts）

> **重要定位说明**：本文件不是“项目类型 → 固定页面模板”的套壳清单，而是你在 Phase 1 阅读真实源码时的**启发式核查视角（Inspection Prompts）**。如果当前项目真实源码用到了某项机制，就把它纳入教学盘点讲透；**如果当前项目根本没用到，绝不硬讲；如果用到了表中未列举的独特机制，优先围绕真实源码展开。**

---

## 一、面对不同项目时的源码核查视角

### 视角 A：前后端分离 / 全栈 Web 应用
- **去源码里核查**：
  1. **网络边界与中间件**：客户端如何发起请求（`fetch` / `FormData`）、服务端如何把原始 HTTP 请求体解析成对象（如 `express.json()`）、静态资源如何托管？
  2. **接口契约与状态码**：有哪些路由（`GET`/`POST`/`PATCH`/`DELETE`）、分别期待什么请求体与返回什么状态码（`200/201/400/404/500`）？
  3. **持久化与 SQL 安全**：数据表结构（主键自增、约束、模式如 `WAL`）、为什么使用参数化查询（`?` 占位符）而不是拼接字符串？
  4. **选型代价**：为什么单机本地用 SQLite（零配置、单文件），什么并发规模下需要换成 PostgreSQL？
- **常见原生沙盘方向**：模拟表单提交 + HTTP/SQL 日志 + 实时内存数据表行变化（支持安全 vs 拼接报错对比及删改操作）。

### 视角 B：纯前端交互 / 画布 / 富文本与状态机应用
- **去源码里核查**：
  1. **状态驱动与引用陷阱**：视图是否由状态树重绘（$UI = f(State)$）？撤销/重做如何处理引用类型（不可变拷贝 `[...arr]` vs 原地 `.push()`）？
  2. **像素坐标系与变换**：是否涉及 `devicePixelRatio` 物理像素校准、`ctx.setTransform`（防止多次 `resize` 累乘缩放）、Pointer Events 与 `touch-action: none`？
  3. **安全渲染与本地存储**：文本/Markdown 解析是否遵循“先 HTML 转义再替换标签”防 XSS？`localStorage` 序列化与损坏数据 `try/catch` 容错边界如何处理？
- **常见原生沙盘方向**：可真实手绘/输入联动的主画面 + 实时刷新的 `past / present / future` 历史栈 + 引用污染对比开关。

### 视角 C：浏览器扩展（Chrome / WebExtension Manifest V3）
- **去源码里核查**：
  1. **MV3 权限与三世界隔离**：`manifest.json` 申请了哪些权限？为什么 `content.js`、`background.js`（Service Worker 按需唤醒与休眠）、`popup` 不能共享内存变量？
  2. **跨沙箱通信与 DOM 隔离**：异步 `onMessage` 为何必须同步 `return true`？注入网页的气泡是否使用 **Shadow DOM** 隔离宿主网页 CSS 污染？
  3. **CSP 与存储差异**：为什么 `popup.html` 禁止内联 `<script>`（CSP 策略）？为什么必须用 `chrome.storage.local` 而不是 `localStorage`？
  4. **加载与双重刷新流**：从 `chrome://extensions` 开启开发者模式加载后，修改不同脚本分别需要刷新扩展还是宿主页？3 个独立 DevTools 在哪里打开？
- **常见原生沙盘方向**：三环境隔离泳道 + 真实词典/生词本交互 + `return true` 缺失复现端口关闭报错。

### 视角 D：CLI 工具 / 构建与处理引擎
- **去源码里核查**：参数解析如何映射为内部配置、流/多阶段管道如何变换数据、`stdout` vs `stderr` 与非零退出码、跨平台路径拼接（`path.join`）。

### 视角 E：AI / LLM Agent 与工作流管线
- **去源码里核查**：确定性外壳与概率性模型输出（JSON Schema / 校验）的边界、ReAct 工具调用循环中 `messages[]` 数组如何逐轮追加 `tool_call` 与 `tool_result`、Token 预算与重试策略。

### 视角 F：安全鉴权 / 协议与加密系统
- **去源码里核查**：信任边界在哪、签名/JWT/OAuth2 PKCE 握手顺序、攻击载荷如何绕过天真实现及硬化后的拦截点。

### 通用第一性原理（适用于任何混合或未列举项目）
1. **找边界**：代码跨越了几个进程、沙箱或网络节点？
2. **找核心变化**：最让新手困惑的状态、坐标或数据结构是在哪个函数里发生关键变化的？
3. **定编码顺序**：先写哪个文件能最快得到一个可运行的“最小脉搏”？

## 二、环节级展示决策参考（严禁连续章节版式雷同）

根据当前章节要讲透的认知对象，灵活选用表达形态，**不预设固定章节顺序**：

| 认知对象 | 推荐表达形态 | 应避免的惰性做法 |
| :--- | :--- | :--- |
| **空间边界与文件分工** | 带箭头连线与虚线隔离框的 SVG 拓扑图 + 点击下钻抽屉 / 折叠目录树 | 只放一排无连线的圆角卡片 |
| **接口契约与数据模型** | 温暖素雅的 `.spec-table` 对照表 + `.causal-chain` 流转带 | 把 5 个接口字段全挤进自然段里 |
| **核心机理因果推演** | **项目原生可操作微沙盘** 或 **Sticky 左文右图**（`.sticky-split`） | 只有两按钮切换预设字符串日志 |
| **轻量术语与进阶深挖** | 行内 `.term-chip` 微释义 + 正文 `.jit-concept` + 折叠 `.deep-dive` | 开篇堆砌一排术语卡片，或把主线必懂原理藏进折叠框 |
| **真·从零编码实战** | 带多语言高亮、**代码↔注解双向联动**与 `data-focus` 折叠的 `.code-walkthrough` | 核心文件 0 注解、行号越界，或所有步骤硬套同一套固定格式 |
