    01 / 先看清为什么需要前后端分离

    TaskFlow：只有 4 个文件的全栈待办应用

    很多刚接触开发的同学会疑惑：既然网页里也能写 JavaScript，为什么不能把待办数据直接存进电脑硬盘里？

    原因在于浏览器是一个受保护的：你打开任何网页，它都无权直接修改你电脑里的文件。因此必须由运行在你本机系统里的 充当“硬盘大管家”，网页通过 请它代劳，把数据存进本地的 （俗称“硬盘持久化”——关掉网页甚至重启电脑，数据依然还在）。

    三层网络边界拓扑 点击下面任意一个白色模块卡片，查看它负责的工作与所在运行环境

    为什么选 Node.js + Express 而不是 Python/Java？

    前后端全部用 JavaScript 编写，不用在两种语言间来回切换。Express 只需要 30 行就能同时搞定静态网页托管和 JSON 接口。如果你更熟悉 Python，完全可以用 FastAPI 替代 server.js。

    为什么选 SQLite（better-sqlite3）而不是 MySQL？

    MySQL/PostgreSQL 需要单独安装数据库服务、配置账号密码和端口；SQLite 直接把整张表存成项目里的单个 taskflow.db 文件，零配置启动。代价是同一时刻只支持单进程写入，当项目需要多台服务器并发写入时再迁往 PostgreSQL。

    核心安全机制 为什么必须用 ? 占位符而不是模板字符串拼接 SQL？

    取消勾选上方复选框并提交 Buy Bob's coffee 时，拼接出的 SQL 变成 VALUES ('Buy Bob's coffee')——输入里的单引号提前闭合了字符串，直接触发 SqliteError（HTTP 500）。使用 ? 占位符后，SQLite 会先编译好语句结构，再把用户输入当作纯文本绑定进去，彻底杜绝标点报错与 SQL 注入。

    底层深挖：db.pragma("journal_mode = WAL") 到底改变了什么？

    SQLite 默认使用回滚日志模式：每次写入数据时都会锁住整个 taskflow.db 文件，此时如果刚好有另一个读请求进来只能排队等待。开启 WAL (Write-Ahead Logging) 后，新写入的数据先追加到旁边的 taskflow.db-wal 文件里，读取请求照常读主文件，读写互不阻塞，个人全栈项目响应会更顺滑。

    Step 2 · 数据库层db.js
    db.js 
    import Database from "better-sqlite3";

const db = new Database("taskflow.db");
db.pragma("journal_mode = WAL");
db.exec(`
  CREATE TABLE IF NOT EXISTS tasks (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,
    completed INTEGER NOT NULL DEFAULT 0
  )
`);

export function listTasks() {
  return db.prepare("SELECT id, title, completed FROM tasks ORDER BY id DESC").all();
}

export function createTask(title) {
  const info = db.prepare("INSERT INTO tasks (title) VALUES (?)").run(title);
  return db.prepare("SELECT id, title, completed FROM tasks WHERE id = ?").get(info.lastInsertRowid);
}

export function toggleTask(id) {
  db.prepare("UPDATE tasks SET completed = CASE WHEN completed = 1 THEN 0 ELSE 1 END WHERE id = ?").run(id);
  return db.prepare("SELECT id, title, completed FROM tasks WHERE id = ?").get(id);
}

export function deleteTask(id) {
  return db.prepare("DELETE FROM tasks WHERE id = ?").run(id).changes > 0;
}
    L3-L4

    打开本地库文件：若 taskflow.db 不存在会自动新建；第 4 行开启 WAL 并发模式。

    L6-L9

    幂等建表与主键自增：IF NOT EXISTS 保证重复启动不报错；PRIMARY KEY AUTOINCREMENT 让每条新任务自动获得递增的唯一 id；SQLite 没有布尔类型，用 0/1 表示未完成/已完成。

    L18-L19

    预编译写入与回查：.run(title) 把参数安全填入 ?；随后用 info.lastInsertRowid 立即查出刚才生成的完整行（含自增 id）返回给前端。

    L23

    SQL 语法 CASE WHEN：相当于 SQL 里的 if/else——如果当前 completed 是 1 就改成 0，否则改成 1，一条语句完成状态翻转。

    L28

    判断是否真删到了数据：.changes 表示受影响的行数，大于 0 说明确实删掉了这条任务，否则说明 id 不存在。

    Step 3 · 接口服务层server.js
    server.js 
    import express from "express";
import { listTasks, createTask, toggleTask, deleteTask } from "./db.js";

const app = express();
app.use(express.json());
app.use(express.static("public"));

app.get("/api/tasks", (req, res) => {
  res.json(listTasks());
});

app.post("/api/tasks", (req, res) => {
  const title = String(req.body?.title || "").trim();
  if (!title) return res.status(400).json({ error: "任务标题不能为空" });
  res.status(201).json(createTask(title));
});

app.patch("/api/tasks/:id", (req, res) => {
  const updated = toggleTask(Number(req.params.id));
  if (!updated) return res.status(404).json({ error: "任务不存在" });
  res.json(updated);
});

app.delete("/api/tasks/:id", (req, res) => {
  const ok = deleteTask(Number(req.params.id));
  res.status(ok ? 204 : 404).end();
});

app.listen(3000, () => console.log("TaskFlow running at http://localhost:3000"));
    L5-L6

    两个核心中间件：express.json() 解析请求体到 req.body（必须写在路由之前）；express.static("public") 让访问根路径时自动返回 public/index.html。

    L13-L15

    可选链 ?. 与输入边界校验：req.body?.title 表示哪怕 req.body 是空也不会报错崩溃；.trim() 去掉首尾空格，若为空则拦截返回 400，创建成功返回 201。

    L18-L20

    动态路由参数 :id：URL 里的 req.params.id 默认是字符串，必须包一层 Number(...) 转成数字再查库；若返回 undefined 则响应 404。

    L25-L26

    无内容响应 .end()：204 No Content 代表删除成功且不返回任何 JSON 体，直接调用 .end() 结束本次 HTTP 连接。

    const listEl = document.getElementById("task-list");
    async function loadTasks() {
      const res = await fetch("/api/tasks");
      const tasks = await res.json();
      listEl.innerHTML = tasks.map(t => `
        <li>
          <span class="${t.completed ? "done" : ""}" onclick="toggle(${t.id})">${t.title}</span>

    document.getElementById("task-form").addEventListener("submit", async (e) => {
      e.preventDefault();
      const input = document.getElementById("task-input");
      await fetch("/api/tasks", {

        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ title: input.value })
      });
      input.value = "";
      loadTasks();
    });
    async function toggle(id) { await fetch(`/api/tasks/${id}`, { method: "PATCH" }); loadTasks(); }
    async function removeTask(id) { await fetch(`/api/tasks/${id}`, { method: "DELETE" }); loadTasks(); }

    05 / 保持服务运行再打开浏览器

    本地启动与排错定位

    新手最易忽略的操作顺序：在终端执行 npm start 后，不要关闭这个终端窗口（服务端需要一直监听 3000 端口），然后打开浏览器访问 http://localhost:3000（不要直接双击 public/index.html，否则 /api/tasks 找不到端口）。

    看浏览器 DevTools (F12 → Network)

    如果点“添加”没反应，先看 Network 面板里请求的状态码：400 是传参为空，404 是路径拼错，Failed to fetch 通常是服务端终端关掉了。

    看运行 node server.js 的终端

    如果状态码是 500 或根本启动不了，立刻切回终端看红色报错堆栈（如 SQLite 语法错、或 EADDRINUSE 端口被旧进程占用）。
