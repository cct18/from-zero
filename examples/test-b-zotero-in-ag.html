    01 / 先看懂这个 25 文件仓库的“两条腿”和“读写分离”

    Zotero in AG：把文献库原生搬进 Antigravity

    先从零理解它到底解决了什么痛点：平时读论文时，Zotero 文献库在桌面上，PDF 在文件夹里，AI 助手在编辑器里，三者割裂。zotero-in-ag 要做的，就是既让 AI 助手能直接查你的文献、读 PDF、帮你写笔记，又让你能在 右侧边栏里像原生软件一样刷分类、看 PDF、划线翻译。

    但这里有一个致命难题：如果 Zotero 桌面端正在开着，我们用 Python 直接去改写它的数据库文件 zotero.sqlite，极容易把用户的文献库写坏甚至报错锁死！因此整个项目确立了最核心的架构铁律——双通道接入 + 严格读写分离：

    • 通道 1（给 AI 用的 ）：通过 src/mcp_server/server.py 暴露 6 个工具给 AI 调用。
    • 通道 2（给人看的 ）：通过 src/sidecar/server.py 启动本地网页服务，渲染文献列表与离线 。
    • 读写分离铁律：查文献、读批注时，只用只读模式悄悄读 zotero.sqlite；要新建富文本笔记时，绝不硬写数据库，而是发 HTTP 请求给 Zotero 自带的 ，请 Zotero 自己安全落盘。

    04 / 为什么工程上要多写这些“防崩代码”

    Sticky 深剖：原子写文件、前端单源打包与选区护盾

    点击左侧任意一条工程决策卡片，右侧固定图解面板会解释它解决的真实故障场景。

    1. 批注缓存为什么先写临时文件，再 os.replace()？

    如果直接打开 zotero_annotations_cache.json 覆盖写入，写到一半电脑断电或程序强退，整个 JSON 文件就会残缺损坏，用户以前划的所有重点批注瞬间全丢！先写进临时文件再原子替换，就像“先在草稿纸抄完整份，再一瞬间把旧纸换掉”，保证文件要么是旧的完整版，要么是新的完整版。

    2. 为什么 8 个前端 ESM 模块要打包成单个 app.js？

    开发时拆成 shield.js、pdf_viewer.js 等 8 个文件非常清爽；但 Antigravity 侧边栏运行在 中。scripts/bundle_frontend.py 把 import/export 剥离后按依赖顺序拼进一个立即执行函数（IIFE）app.js，一次加载即生效且不会污染全局窗口变量。

    3. 为什么 PDF 划词容易“突然全选整页”？选区护盾怎么修？

    PDF 里的文字并不是连续段落，而是一个个悬浮的绝对定位 <span>。鼠标稍微滑到行尾空白或双栏中缝，浏览器就找不到当前文字节点，选区会瞬间跳到页面末尾。shield.js 先按垂直高度（clientY）锁定鼠标所在行，再分栏过滤并投影到最近字符，彻底消除了跳选闪烁。

    底层语法补充：为什么 FastAPI 接口里要写 await asyncio.to_thread(...)？

    FastAPI 是异步并发框架（就像一个服务员同时照看 10 桌客人），而 Python 自带的 sqlite3 查询是同步阻塞的。如果直接在异步函数里查大数据库，整个服务员会被卡住，期间所有前端请求都得干等。asyncio.to_thread 把耗时 SQL 扔进后台线程池去跑，主线程立刻腾出手响应别的请求。

    核心 1 · 无锁只读驱动src/core/db.py（连接策略节选）
    src/core/db.py 
    import time
import sqlite3
from contextlib import contextmanager

@contextmanager
def _get_connection(self):
    conn = None
    uri_ro = f"{self.db_path.as_uri()}?mode=ro"
    for attempt in range(2):
        try:
            conn = sqlite3.connect(uri_ro, uri=True, timeout=0.6, isolation_level=None)
            conn.execute("PRAGMA busy_timeout = 600;")
            conn.row_factory = sqlite3.Row
            conn.execute("SELECT 1 FROM collections LIMIT 1;")
            break
        except sqlite3.OperationalError as e:
            if conn:
                try: conn.close()
                except Exception: pass
                conn = None
            if "locked" in str(e).lower() and attempt < 1:
                time.sleep(0.1)
                continue
            break

    if conn is None:
        uri_immutable = f"{self.db_path.as_uri()}?mode=ro&immutable=1"
        conn = sqlite3.connect(uri_immutable, uri=True, timeout=5.0, isolation_level=None)
        conn.row_factory = sqlite3.Row

    try:
        yield conn
    finally:
        if conn: conn.close()
    L5-L6, L32-L34

    语法 @contextmanager 与 yield：这是 Python 的上下文管理器写法。外层写 with self._get_connection() as conn: 时，执行到 yield conn 把连接借出去用，用完无论成功还是报错，finally 都会自动关闭连接防止内存泄漏。

    L8, L11-L14

    首选 mode=ro 实时感知 WAL：self.db_path.as_uri() 把本地路径转成 file:///... URI，配合 uri=True 和 mode=ro，就能在 Zotero 开着时实时读到最新增删的文献；第 14 行执行一句轻量查询探活，确认没被锁死。

    L26-L29

    Windows 独占锁保底回退：如果重试两次仍被 Windows 锁住（conn is None），立刻切到 mode=ro&immutable=1，告诉 SQLite “别去检查锁文件了，直接当静态只读文件读”，彻底解决与 Zotero 桌面端的冲突。

    核心 2 · 防路径穿越 PDF 定位src/core/storage.py
    src/core/storage.py 
    import re
from pathlib import Path
from typing import Optional

def resolve_pdf_path(self, attachment_key: str, raw_path: Optional[str] = None) -> Optional[Path]:
    if not attachment_key or not re.match(r"^[A-Za-z0-9]{8}$", attachment_key):
        return None

    storage_root = self.storage_dir.resolve()
    folder = (self.storage_dir / attachment_key).resolve()

    try:
        folder.relative_to(storage_root)
    except ValueError:
        return None

    if folder.exists() and folder.is_dir():
        if raw_path and raw_path.startswith("storage:"):
            fname = raw_path[len("storage:"):].strip()
            cand = (folder / fname).resolve()
            try:
                cand.relative_to(storage_root)
                if cand.exists() and cand.is_file() and cand.suffix.lower() == ".pdf":
                    return cand
            except ValueError:
                pass
        pdf_files = list(folder.glob("*.pdf"))
        if pdf_files:
            return pdf_files[0].resolve()

    # 仅当数据库提供 Linked File 绝对路径时生效，Web 端绝不传入 raw_path
    if raw_path and not raw_path.startswith("storage:"):
        abs_cand = Path(raw_path).resolve()
        if abs_cand.exists() and abs_cand.is_file() and abs_cand.suffix.lower() == ".pdf":
            return abs_cand
    return None
    L6-L7

    正则 ^[A-Za-z0-9]{8}$ 门禁：^ 表示开头，$ 表示结尾，中间只允许刚好 8 位字母或数字。像 ../../etc 这种包含斜杠或点号的恶意输入第一关就会被直接打回 None。

    L9-L15

    .resolve() + .relative_to() 双保险：.resolve() 会把路径里的 .. 和软链接全部展开成真实绝对路径；再用 relative_to(storage_root) 检查它是不是还在 storage 根目录里面，一旦逃出就会抛出 ValueError 被拦截。

    L31-L35

    外链 PDF 的信任边界：有些 Zotero 用户习惯“链接文件”而非复制进 storage/。代码只允许从只读 SQLite 内部查出来的 raw_path 走这条分支，而网页 HTTP 接口 /api/pdf/{key} 绝不传 raw_path，守住了外部请求的安全边界。

    def normalize_and_validate_chat_endpoint(base_url: Optional[str]) -> str:
    url = (base_url or "").strip().rstrip("/")
    if not url:
        return "https://api.deepseek.com/v1/chat/completions"
    parsed = urllib.parse.urlparse(url)
    if parsed.scheme not in ("http", "https"):
        raise ValueError(f"不支持的协议 '{parsed.scheme}'")
    hostname = (parsed.hostname or "").lower().strip()

    # 第 1 层：直接拦截云平台元数据域名
    if hostname in ("metadata.google.internal", "instance-data"):
        raise ValueError("禁止访问链路本地/云平台元数据地址")

    # 第 2 层：拦截 0xa9fe01a9（十六进制）或 2852039166（十进制整数）变形 IP
    val = int(hostname, 16) if re.match(r"^0x[0-9a-f]+$", hostname) else (int(hostname) if hostname.isdigit() else None)
    if val is not None and ipaddress.ip_address(val).is_link_local:
        raise ValueError("禁止访问链路本地/云平台元数据地址")

    # 第 3-4 层：标准 IPv4/IPv6 与 socket.inet_aton（防八进制/点分十六进制）
    try:
        if ipaddress.ip_address(hostname).is_link_local:
            raise ValueError("禁止访问链路本地/云平台元数据地址")
    except ValueError:
        pass
    try:
        if ipaddress.ip_address(socket.inet_aton(hostname)).is_link_local:
            raise ValueError("禁止访问链路本地/云平台元数据地址")
    except Exception:
        pass

    return url if url.endswith("/chat/completions") else (f"{url}/chat/completions" if url.endswith("/v1") else f"{url}/v1/chat/completions")
